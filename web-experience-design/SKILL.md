# 网页体验设计

把任务、内容、视觉、交互、动态素材和空间关系组织成能实现、能检查、能回滚的页面方案。先解决当前任务和信息层级，再选择视觉和技术表达；不因为页面同时出现界面、动效或三维词汇就加载全部方法。

## 先确定本轮范围

开始前记录以下输入，并沿用已有结论：

```text
目标：<用户要完成的任务或体验>
真实内容：<文字、图片、数据、素材和状态>
既有成果：<现有页面、组件、视觉变量、已确认方向>
关键约束：<设备、输入、性能、加载、输出和技术栈>
本轮范围：<新页面 / 局部迭代 / 动效 / 动态素材 / 空间叙事>
验证环境：<浏览器、设备、截图、操作或其他可观察环境>
```

按范围选择进入点：

- **点名的小改动**：直接修改指定元素，保持现有结构和视觉变量；只在样式变化影响布局时检查目标视口。
- **新界面或整体改版**：先写产品事实、主角、主动作、真实内容和灰度结构，再确定一个推荐视觉方向；用户明确要求比较时才制作多方向。
- **已有页面的视觉优化**：保留有效品牌资产和组件习惯，先建立基线，从源头修复问题，不把无关业务重构混入本轮。
- **独立交互或动效**：进入“交互契约”，只补受影响的状态和时间关系。
- **空间化页面或沉浸式叙事**：进入“素材与空间”，先做低成本分层试作，再决定是否需要三维、视频或逐帧方案。
- **只读评审**：只交付证据、问题和建议，不自动生成新方向或修改代码。

需要具体视觉方向、素材、滚动、评审或工具流程时，按需读取：

- [设计方向](references/design-direction.md)：产品事实、删减、主视口灰度、方向收敛和差异检验。
- [视觉语言](references/visual-language.md)：字体、色彩、空间、图标、材质和减法精修。
- [素材](references/media.md)：素材来源、生成提示词、实时三维和视频选择。
- [动效](references/motion.md)：界面过渡、反馈、时长和检查。
- [滚动叙事](references/scroll-narrative.md)：滚动驱动的页面叙事和区块出场。
- [显式探索](references/task-explore.md)：用户明确要求多方向或版式比较时读取。
- [只读评审](references/task-review.md)：只读 UI/UX 评审时读取。
- [视觉评审派发协议](references/visual-review.md)和[轻量 UX 走查派发](references/ux-review.md)：有可隔离评审执行者时读取。
- [来源证据](references/source-evidence.md)：需要追溯方法来源、案例参数或时间戳时读取。

## 1. 先定任务、内容和信息结构

列出核心任务、主要内容、模块职责、模块关系和关键操作。先确定功能框架，再决定视觉方向；不要用颜色、字体或主视觉遮住任务路径的问题。[t=0:25]–[t=1:15] V02

把真实内容放进第一版：使用实际文字长度、图片比例、数据密度、输入状态和失败状态检查层级、布局、阅读顺序和操作成本。每屏先明确一个主角和一个主动作；同权重的次要动作或装饰优先合并、降级或移出首要路径。[t=5:20]–[t=6:08] V02

成功条件：能够说明每个模块服务的任务、输入和输出；页面承载真实内容，而不是只有视觉外壳。

## 2. 形成视觉方向和稳定规则

从少量确实相关的参考中提取配色、布局与留白、字体与层级、形状与比例、材质与光影、动效六类规则。区分跨页面稳定规则与可替换主题变量：[t=1:25]–[t=5:04] V02

- 稳定规则包括任务路径、阅读层次、组件尺寸、对齐关系、状态反馈和响应式边界。
- 主题变量包括配色、字体组合、材质、光影、装饰和主视觉素材。

新界面先画主视口灰度结构，验证内容层级、主动作和关键状态；只有另一端会改变布局或输入时才补另一端。结构或核心交互不成立时退回修改，不靠主视觉掩盖。

默认对外只深化一个推荐方向。用户明确要求比较时，按[显式探索](references/task-explore.md)制作指定数量的方向，并用同一组真实内容和视口比较。切换主题不应要求重写信息架构；新增组件要能分别说明放置位置、操作方式和采用的视觉变量。

## 3. 写清交互契约

每个交互都记录触发器、反应对象、变化机制、时间关系和结束或恢复状态：

```text
触发或连续输入：<点击 / 悬停 / 滚动 / 拖拽 / 键盘 / 时间 / 外部状态>
反应对象：<实际变化的元素>
变化机制：<位移 / 变形 / 显隐 / 帧切换 / 布局变化 / 空间变化>
时间关系：<持续时间、顺序、并行、同步或连续跟随>
结束与恢复：<停留、循环、回到初始状态、接续下一状态>
```

少量前后状态优先使用项目已有样式与过渡；连续输入交给输入计算；多个元素的布局联动使用能表达布局变化的能力；多个动作需要顺序、并行或进度同步时使用时间线。对滚动、拖拽和指针跟随写出边界、失焦、触摸和键盘行为，避免只描述“有动效”。[t=2:04]–[t=4:12] V11

## 4. 组织素材和空间关系

按用途拆分环境背景、空间边界、过渡层、关键对象、动态素材和交互反馈。每份素材记录承担的内容、观看区域、组合条件、加载成本和缺口。[t=0:32]–[t=2:15] V13

需要空间层次时，把环境轮廓、主体和装饰拆成可独立控制的层，分别安排前后关系、位置、缩放、遮挡和变化速度。跨场景重复的主体固定轮廓、比例、颜色和材质等稳定特征，把环境、动作、状态和镜头条件分开描述。

动态素材的内部运动和页面中的位置变化分开控制；需要循环或换场时检查首尾状态、接缝、叠影、方向和内容接续。先用二维分层、短片段或低分辨率素材验证构图、遮挡和节奏，再提高分辨率和实现复杂度。[t=3:27]–[t=5:20] V13

## 5. 选择最小实现方式

沿用项目已经能够清楚表达需求的能力，再按控制精度选择方案：

| 需求 | 先考虑 |
| --- | --- |
| 少量状态、悬停、点击和简单反馈 | CSS 或项目已有过渡能力 |
| 鼠标、触摸、拖拽或其他连续输入 | 原生 JavaScript 或项目已有输入层 |
| 布局变化和手势联动 | Motion 或项目已有布局状态能力 |
| 多对象先后、并行或进度同步 | GSAP 或项目已有时间线能力 |
| 二维分层、蒙版和按状态选图 | CSS、SVG 或 Canvas |
| 真实物体、灯光、相机和自由视角 | Three.js、React Three Fiber 或项目已有三维能力 |
| 视频需要按输入索引状态 | 拆帧、背景处理、精灵图或其他可索引素材 |

工具是实现选项，不是前置条件。简单状态先用现有能力；只有控制精度、时间组织、渲染方式或输出格式确实需要时才增加依赖。

## 6. 做代表性试作并取得真实证据

选最能暴露问题的一页、一个核心流程或一段场景接续做试作。先检查信息层级、构图、遮挡、方向、首尾接缝、输入映射和加载成本，再铺开其他页面。

在目标视口运行并查看真实画面。截图、序列图或操作记录只能证明对应状态；截图文件存在不等于已完成视觉验收。没有可运行环境或看图能力时，明确标记未验证实际视觉或交互。能派隔离且具备观察能力的独立评审者时，对新界面、整体改版或一整页润色派一轮评审；没有条件时自检并记录未独立评审。

每轮只改一个主要变量，记录位置、问题、目标、保留项和前后证据。大改前保留回滚点，避免同时改变布局、字体、素材和动效而失去原因追踪。[t=5:15]–[t=6:24] V02；[t=1:20]–[t=2:05] V19

## 7. 回归检查和交付

按本轮范围检查：

- 主要任务、信息层级和真实内容仍然清楚。
- 组件、素材和空间层的对齐、间距、遮挡和边界成立。
- 触发、响应、停留、恢复、循环和接续符合交互契约。
- 输入方向、帧顺序、首尾接缝和动态素材合成正确。
- 关键视口、键盘操作、加载成本和实际运行环境已经检查。
- 未修改区域保持原有结果；未验证部分明确写出。

交付内容按需要包括任务与信息结构、视觉规则、交互契约、素材职责、实现方式理由、试作证据、评审结果、回归结果和待验证项。过程文件、截图和评审记录放在项目任务目录，不写进 skill 安装目录。

## 能力边界

本技能负责网页和界面体验的任务拆解、视觉判断、交互契约、空间关系和验证标准。纯业务逻辑、接口、数据模型、无界面变化的代码整理以及与网页无关的单独素材制作使用项目已有工程技能；已明确改法的小改动直接处理，不重新启动完整设计流程。
