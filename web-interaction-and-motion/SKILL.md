# 网页交互动效与工具选择

> 验证状态：尚未通过执行新的网页项目验证；方法根据 V09、V11、V14 的转写，以及全部抽取的联系表和关键帧，于 2026-11-27 重建。
> 视频展示了方法和工具边界，但没有提供完整的实现代码库。

先说明“什么输入让哪个对象怎样变化”，再判断哪些部分需要素材，哪些部分需要程序控制。作者的方法可归纳为：描述效果 → 拆分控制需求 → 选择表现方式 → 准备可用素材 → 映射输入与状态 → 检查恢复和衔接。

下面是对来源方法的通用化归纳；时间戳指向作者案例，其他对象和使用场景属于迁移，尚未逐一执行验证。按需求选择分支；原始工具、角色和参数见[来源证据](references/source-evidence.md)。

## 与相邻技能分工

本技能负责可观察的动效行为、输入映射、时间组织和动态素材状态。先按核心问题选择入口：

| 当前核心问题 | 使用技能 |
| --- | --- |
| 页面任务、信息层级、组件规则和视觉迭代 | `interface-design-process` |
| 触发器、状态、输入响应、时间线、逐帧素材或动效实现 | `web-interaction-and-motion` |
| 空间层次、遮挡、场景接续、沉浸式叙事或跨场景主体一致性 | `immersive-web-storytelling` |

本技能不负责完整的信息架构或视觉方向；动效只有在改变页面任务、空间叙事或组件规则时，才把约束回写给相邻技能。

## 应用前先代入项目

确定目标效果、输入方式、反应对象、已有资产和现有工程。再区分是一次状态变化、连续输入控制、按时间播放，还是多对象联动；只启用需要的制作步骤。

## 步骤

### 1. 用可观察的语言命名动效

不要从“做一个酷炫效果”开始。先写触发器、反应对象、运动方式和结束状态：

```text
目标效果：<希望用户看到或感受到什么>
触发或连续输入：<当前项目支持的输入，以及何时生效>
反应对象：<实际需要变化的元素>
变化机制：<位移 / 变形 / 显隐 / 帧切换等>
时间关系：<持续时间、顺序、同步或连续跟随>
结束与恢复：<停留 / 循环 / 回到初始状态 / 接续下一状态>
```

V09 逐项给出过这些可复用名称：流体扰动、流体蒙版透视、透镜跟随双语揭示、鼠标驱动三维碰撞、点击触发产品展示、点击触发空间转场、粒子卷动、液体折射、像素网格错位、鼠标跟随聚光、布料模拟、弹性拉伸。[t=0:00]–[t=1:08] V09

这些名称帮助把视觉感觉说具体。按当前效果选择描述，不要求复刻案例网站或把所有效果放进一个项目。[t=0:00]–[t=1:08] V09

### 2. 在生成式素材和代码控制之间做判断

- 形态、质感、颜色和整体氛围主要由素材决定时，可用已有素材或生成式图像、视频准备外观。[t=0:00]–[t=0:32] V11
- 需要确定的路径、周期、时序或输入响应时，把这些控制交给代码，避免仅靠生成过程保证精确行为。[t=0:32]–[t=1:02] V11
- 两者可以组合：先生成素材，再用代码安排出现时间、位置、衔接和交互。[t=1:02] V11

✔ 成功：需求中能明确区分“素材长什么样”和“素材何时、在哪里、如何响应”。

### 3. 按输出需求选择排版方式（需要视频输出时）

需要把素材编排成视频时，再根据已有资产和工程选择排版方式。以下工具是来源视频的例子，保留“模板和逐帧控制”与“网页式排版”的判断，不要求安装指定工具：

- **Remotion**：把样式、出场动作、文字和图片的帧位置做成可重复模板；适合已有模板只换内容和时间。[t=1:02]–[t=2:04] V11
- **HyperFrames**：用更接近网页的方式排列文字、图片和视频，再安排它们出现；适合已有网页动画或更偏页面结构的工程。[t=1:02]–[t=2:04] V11

不要先背一长串工具名。先告诉 AI 想要的效果和已有工程，让它在保留原有模板的前提下给出小段演示；已有工程优先沿用原工程。[t=6:28]–[t=6:45] V11

### 4. 按状态和时间关系选择控制方式

- **少量前后状态**：先用现有样式与过渡能力表达触发、变化和恢复；来源用 CSS 悬停反馈示范。[t=2:04]–[t=2:35] V11
- **连续输入**：读取输入并计算位置、方向或状态；来源用原生 JavaScript 读取鼠标位置示范。[t=2:35]–[t=3:08] V11
- **多个元素的布局联动**：选择能组织布局变化的能力，减少逐个计算位置；来源工具示例是 Motion。[t=3:08] V11
- **动作顺序和同步**：用时间线表达先后、并行或与进度的关联；来源工具示例是 GSAP。[t=3:08]–[t=4:12] V11

优先复用现有工程能清楚表达需求的能力。把上述名称视为工具类别的示例，按当前技术栈选择；并非一次动效需要同时使用这些库。[t=6:28]–[t=6:45] V11

### 5. 按画面关系选择二维或三维表现

- **二维素材叠放或按状态选图**：先判断分层绘制能否表达目标；来源用 Canvas 示范二维画面组织。[t=4:12]–[t=5:20] V11
- **真实三维关系**：需要物体、灯光、相机或视角变化时，准备相应场景与几何；来源用 Three.js 示范。单张图像不会自动具备三维结构。[t=4:12]–[t=5:20] V11
- **输入计算与画面呈现分开**：先计算要显示的状态，再由呈现层绘制。来源是 JavaScript 选图、Canvas 显示的组合。[t=4:12]–[t=4:55] V11

检查视觉关系是否成立：附着元素是否跟随表面，角度和遮挡是否一致，再定位单项修改。来源中的建筑表面只是这类问题的一个例子。[t=5:20]–[t=6:28] V11

### 6. 把视频变成可索引的互动素材（按需）

需要按输入或时间选择具体画面时，才使用逐帧方案；普通悬停或布局变化可以直接走前面的状态控制分支。作者用人物演示，迁移时可替换为当前项目的图像主体：

1. 准备首帧和关键状态，再生成或选取能够覆盖所需变化的视频。[t=1:02]–[t=2:11] V14
2. 把所需片段拆成有顺序的帧；按实际素材与交互精度确定需要保留的帧。[t=1:02]–[t=1:25] V14
3. 需要与网页背景合成时去除素材背景；使用色幕时，让背景均匀，并避免与主体颜色冲突。[t=2:11]–[t=2:40] V14
4. 可把多帧打包成精灵图并按索引显示。按当前图像尺寸、帧数和加载预算确定分组；来源中的分组数字仅作为例子。[t=1:25]–[t=2:11] V14

✔ 成功：帧顺序和索引正确，合成边缘干净，能显示需要的全部状态。图集减少了独立文件数量；总体积和加载效果仍按当前项目实测。

### 7. 按后续处理反推素材约束（按需）

- 如果需要色幕抠图，选择与主体有区分的均匀背景色，去除不需要的背景阴影；来源用绿幕、蓝幕示范。[t=2:11]–[t=4:29] V14
- 明确方向使用的参照系，并让素材动作与输入映射保持一致；来源以屏幕观看者为准，避免生成工具反转左右。[t=2:11]–[t=3:18] V14
- 明确哪些部分运动、哪些外观和位置应保持稳定，减少素材在不相关区域漂移。[t=2:11]–[t=3:18] V14
- 复杂动作按时间拆解，写清关键状态、镜头条件和应保留的部分。[t=3:18]–[t=4:29] V14
- 一段素材无法覆盖完整运动时，拆成可衔接的片段，约定各段首尾状态；需要循环时，可让首尾回到相同状态并检查连接。来源用上下半圈拼接和相同首尾帧示范。[t=3:18]–[t=4:29] V14
- 需要动作参考时，把外观和运动分开输入，并检查镜头、主体占位和画面边界是否适合后续合成；来源用舞蹈动作和角色参考示范。[t=4:29]–[t=5:41] V14
- 动作参考中的原主体外观会干扰目标外观时，可先提取只保留运动结构的中间参考，再与目标外观组合；来源使用深度白模去除原人物的面貌和服装信息。这是按素材与生成工具选择的处理分支。[t=4:29]–[t=5:41] V14

### 8. 把输入或播放进度映射到素材状态

先按用户期望明确主要模式。来源给出三种做法，可按当前对象和输入方式迁移：

1. **连续输入映射**：输入的位置、方向或进度对应素材状态；来源是鼠标方向映射到人物帧。[t=5:41]–[t=6:50] V14
2. **事件触发播放**：触发后播放指定片段，再按需要恢复；来源是悬停和点击反馈。[t=5:41]–[t=6:50] V14
3. **时间同步**：播放进度对应素材帧，检查音画或多个动作的衔接；来源是音乐同步。[t=5:41]–[t=6:50] V14

逐帧方案的交接信息包括：素材片段、背景处理、采样与打包方案、输入到帧的对应关系、触发后的播放和恢复行为。涉及的字段按方案填写。[t=6:50]–[t=7:28] V14

若项目需要组合多种模式，补充它们的切换与恢复规则；这是应用时的迁移要求，不是来源视频已经提供的组合实现。

### 9. 做交互回归检查

检查每个状态的触发、响应、恢复和边界：

- 连续输入停止时，素材是否停在适合停留的状态；排除不适合长时间显示的过渡帧，来源中的闭眼帧是人物素材的例子。[t=5:41]–[t=6:05] V14
- 点击动作是否完整播放，回弹和恢复是否自然。[t=5:41]–[t=6:20] V14
- 按选用模式检查循环接缝、输入方向、状态顺序和恢复行为。[t=5:41]–[t=6:50] V14
- 存在表面附着或三维关系时，检查文字、图形和遮挡是否与表面同步。[t=5:20]–[t=6:28] V11

交付与任务相符的结果：效果描述、选择实现方式的理由、需要的素材与控制规则，以及实际检查结果。未选用的分支不要求产出额外素材或代码。
