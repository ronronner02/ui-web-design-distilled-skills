# 界面设计与迭代方法

> 验证状态：尚未通过实际执行 UI 项目验证；方法根据 Whisper 转写和对 V02、V19 画面的检查，于 2026-11-27 重建。
> 两个来源视频展示了流程和示例，但没有提供完整的可运行代码库。

围绕当前项目，依次解决“承载什么任务、怎样组织信息、用什么视觉规则、如何反馈和验证”。保留作者拆参考、固定规则、控制修改范围的思路，具体模块和参数随项目确定。

本技能把作者案例归纳为可迁移的方法。时间戳指向原案例，其他应用场景是方法迁移，尚未逐一执行验证。需要核对原始对象、参数和画面时，阅读[来源证据](references/source-evidence.md)。

## 与相邻技能分工

本技能负责页面任务、信息架构、视觉系统和基于真实内容的迭代。遇到以下情况时切换到对应技能：

| 当前核心问题 | 使用技能 |
| --- | --- |
| 页面任务、模块关系、信息层级、组件规则或视觉迭代 | `interface-design-process` |
| 触发器、输入响应、状态切换、时间线、逐帧素材或动效实现 | `web-interaction-and-motion` |
| 空间层次、遮挡、场景接续、沉浸式叙事或跨场景主体一致性 | `immersive-web-storytelling` |

本技能不承担纯业务逻辑、接口实现或独立动效工程；只有在这些内容影响页面任务或视觉规则时，才记录其设计约束。

## 适用场景

- 需要从需求开始组织新界面的功能、内容和视觉设计。
- 已有可用界面，需要改善布局、层级、风格或交互反馈。
- 需要从参考作品中提取可复用的视觉规则，而不是让 AI 猜“更高级”。
- 需要维持多个页面、状态或主题之间的设计一致性。
- 需要把一次性大提示词改成可检查、可回滚的迭代流程。

## 应用前先代入项目

从用户需求和现有工程中确定：核心任务、主要内容、已有成果、要保留的特点和本轮问题。已有结论直接复用；只补充影响本轮设计的信息。新设计从结构开始，局部改进从对应问题进入，无需重做全部阶段。

## 工作方法

### 1. 先搭功能框架

先列出产品的核心模块、模块职责和模块之间的关系。不要从“做得漂亮”开始，也不要让 AI 从空白页面自行猜产品结构。[t=0:25]–[t=1:15] V02

按用户任务确定模块数量和名称，写清每个模块负责什么、与哪些内容或操作连接。保留作者先说明模块关系的做法，实际结构由当前项目决定。[t=0:55]–[t=1:15] V02

如果已有可用界面或阶段成果，从它继续，说明哪些信息、素材、视觉特点和交互应保留；先确定问题范围，再决定改动范围。[t=0:35]–[t=0:48] V19

✔ 成功：能画出模块关系图，并能说明每个模块的输入、输出和关联对象；第一版页面能承载真实功能，而不是只有视觉壳。

### 2. 用真实内容做第一轮审查

在可检查的第一版中放入与用途相符的真实内容：文字、图片、数据、输入或操作。观察内容长度和密度怎样影响阅读、布局与操作，避免仅凭理想占位内容判断设计。[t=5:20]–[t=6:08] V02

✔ 成功：你能指出具体位置的具体问题，例如某个列表挤在一起、某个侧栏离条目太远，而不是只说“整体不够高级”。

### 3. 按六个维度拆解视觉参考

找到一到几个你确实喜欢的界面，把参考交给 AI，并要求它按下面六个维度分析；不要只说“更漂亮”或“更高级”。[t=1:25]–[t=2:24] V02

1. **配色**：背景、正文、辅助文字和强调色分别占多少，强调色在哪里出现。
2. **布局与留白**：哪些区域紧凑，哪些区域舒展，间距如何形成阅读节奏。
3. **字体与层级**：标题、正文、辅助信息的大小、重量、对比和阅读顺序。
4. **形状与比例**：卡片、按钮和列表的尺寸，圆角、边框和比例关系。
5. **材质与光影**：表面质感、边缘、阴影方向、发光范围和明暗层次。
6. **动效**：出现、切换、点击反馈和转场分别如何发生。[t=1:45]–[t=2:15] V02

把分析结果转写成项目自己的视觉规则，再结合你的内容和功能调整。参考是输入，最终规则必须服务于你的产品。[t=2:15]–[t=2:24] V02

### 4. 固定风格基本元素

为每个主题建立一份小型风格表，至少记录：主背景、文字层级、强调色、边界、圆角、阴影、表面材质、主要动效和主题元素。[t=2:35]–[t=3:12] V02

把页面拆成两层：

- **共性规则**：内容模块和底层链接关系、页面布局和阅读层次、组件尺寸和对齐关系、操作反馈和交互节奏。[t=4:05]–[t=4:32] V02
- **主题变量**：配色、材质、光影和主题装饰。新增卡片、按钮或列表时，位置和操作遵循共性规则，视觉质感遵循当前主题。[t=4:45]–[t=5:04] V02

✔ 成功：你可以切换主题而不重写信息架构；新增一个组件时，能分别回答“它放在哪里、怎么操作”和“它使用什么颜色、边界、阴影”。

### 5. 按使用方式检查动态素材（按需）

如果界面使用循环动画，明确首尾衔接要求，并观察完整循环中的运动、光影和视觉节奏。时长由当前体验决定；没有循环需求时跳过这项检查。[t=3:25]–[t=4:00] V02

作者案例中的具体时长和无法辨认的提示词记录在来源证据中，不作为项目默认配置。

✔ 成功：循环播放至少两次时，首尾连接处没有明显跳帧、音画断裂或光影突变。

### 6. 用四要素写修改请求

每次修改都写清四件事：

1. **位置**：哪个页面、哪个组件、哪个状态。
2. **问题**：当前行为或视觉结果是什么，为什么不满意。
3. **目标**：希望改成什么样，必要时给出时长、比例或间距。
4. **保留**：哪些已满意的部分必须保持不变。[t=5:15]–[t=5:52] V02

可以直接使用这个提示结构：

```text
位置：<页面 / 组件 / 状态>
问题：<当前结果和具体问题>
改成：<目标行为、视觉或数值>
保留：<必须保持的元素>
```

把动作主体和保留对象分开描述，再按当前体验调整时长或幅度。这样反馈既能指出要改什么，也能约束改动范围。[t=5:36]–[t=5:52] V02

### 7. 一轮只改一件事，并保留回滚点

把多个想法记下来分轮处理。每轮只改一个问题，改完后打开界面亲自检查；准备调整大块布局前，先保存一个可回退版本。[t=6:08]–[t=6:24] V02；[t=1:45]–[t=2:05] V19

细微数值也通过实际操作比较：围绕一个反馈参数尝试不同值，检查是否清楚、自然，再保留适合当前组件的结果。来源示例里的缩放比例不作为通用默认值。[t=6:08]–[t=6:24] V02

### 8. 把每轮生成接到实际检查

每轮修改后，在实际运行环境中操作相关状态，保留截图并检查结果，再进入下一轮。来源案例使用浏览器；迁移到其他界面时，使用项目实际支持的预览或运行环境。[t=1:56]–[t=2:05] V19

检查至少包括：

- 主要信息和辅助信息的阅读层级是否仍然清楚。
- 组件对齐、间距和边界是否保持一致。
- 交互反馈是否跟随既定节奏。
- 当前项目的真实内容是否造成溢出、拥挤或操作不清。
- 本轮未修改的区域是否保持不变。

✔ 成功：每轮都有可比较的前后截图；问题可以定位到本轮改动，而不是在多项同时变化后凭感觉猜原因。

## 本轮输出与检查

按当前问题保留有用的结果：结构与模块关系、视觉规则、修改请求、前后对比和待解决问题。局部调整不要求重新生成完整设计文档。按本轮范围检查适用项：

- [ ] 涉及结构调整时，已写清相关模块、职责和关系。
- [ ] 已有与本轮交付相符、可供检查的界面版本。
- [ ] 已用实际内容检查相关区域。
- [ ] 确立视觉方向时，已按六个维度拆参考。
- [ ] 涉及新组件或主题时，已记录应遵循的稳定规则与风格变量。
- [ ] 修改请求包含位置、问题、目标、保留项。
- [ ] 每轮只改一件事，并保留截图。
- [ ] 大改动前有回滚版本。
- [ ] 已在当前项目的运行环境中操作并检查相关状态。
