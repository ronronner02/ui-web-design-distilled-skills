# 界面设计流程：来源证据

## 原案例与方法的关系

本文件保留视频中的具体对象、数值和画面，供追溯作者做法。`SKILL.md` 将这些做法归纳为当前项目可以采用的流程；应用对象、模块和参数由需求决定。

| 原案例 | 保留的思路与技巧 | 应随项目替换的部分 |
| --- | --- | --- |
| 创作面板中的六个模块 | 先说明职责与关系，再组织界面 | 模块名称、数量、内容和操作 |
| 多版看板与不同主题 | 复用已有成果，分开稳定结构与视觉变量 | 页面类型、配色、材质和装饰 |
| 封面、标题与按钮反馈 | 定位问题，说明目标与保留项，单轮比较效果 | 修改对象、动作时长、幅度和比例 |
| 浏览器操作与截图 | 让生成结果接受实际检查 | 当前项目的运行环境和检查范围 |

## V02：先做功能还是先做 UI

| 时间 | 画面 / 说法 | 可复用结论 |
| --- | --- | --- |
| 0:25–0:55 | 先理清功能框架，再做 UI，再用真实内容边用边改；三个版本风格不同但规则一致。 | 先结构、后视觉、再迭代。 |
| 0:55–1:15 | 列出工作台、作品库、创作台、选题池、日历表、数据库及其关系。 | 先写模块和关系。 |
| 1:25–2:24 | 拆配色、布局留白、字体层级、形状比例、材质光影、动效。 | 把审美意见变成六维规则。 |
| 2:35–3:12 | 固定每种风格的基本元素。 | 建立主题变量。 |
| 4:05–5:04 | 保留共性规则，变化配色、材质、光影和主题元素。 | 分离结构层和主题层。 |
| 5:36–5:52 | 封面转场示例：位置、问题、改法、保留项；时长调到 650 毫秒。 | 修改请求必须可定位、可验收。 |
| 6:08–6:24 | 每轮只改一件事；按钮按下缩放比较 94% 和 96%；大改前保留版本。 | 控制变量并保留回滚点。 |

## 来源示例中的参数

- 六个模块是来源创作面板的信息架构；通用方法是先厘清当前产品的模块职责和关系。[t=0:55]–[t=1:15] V02
- 光球动画使用 6 秒无缝循环。完整提示词在画面中不可清晰辨认，不作为可复制模板；时长按当前素材确定。[t=3:25]–[t=4:00] V02
- 封面转场调到 650 毫秒，同时保留标题；方法是分清修改对象与保留对象，再用明确参数描述期望。[t=5:36]–[t=5:52] V02
- 按钮按下缩放比较 94% 与 96%，作者选择后者；方法是通过实际操作比较细微反馈，比例不是通用默认值。[t=6:08]–[t=6:24] V02
